Most runtime issues come from a mismatch between model file, feature
flags, backend, context size, or command arguments. Start from the
smallest model that exercises the feature you need.

```bash [Terminal]
llama-crab-server --model /models/small-chat.gguf
```

The high-level [Troubleshooting](/troubleshooting) page covers the
top-level failure modes (server start, streaming, multimodal, Tauri IPC,
TS client validation). This page focuses on the model, backend, and
allocation issues that usually surface first.

## Model file not found

Download the model files required by the feature you are testing, then
pass their absolute paths to your application or server process.

```bash [Terminal]
llama-crab-server --model /absolute/path/to/model.gguf
```

In 0.1.8 the `hf-hub` cargo feature also lets `--model` accept a
Hugging Face repository id; combine it with `--hf-filename` to pick the
GGUF file inside the repo:

```bash [Terminal]
llama-crab-server \
  --hf-hub \
  --model Qwen/Qwen2.5-0.5B-Instruct-GGUF \
  --hf-filename qwen2.5-0.5b-instruct-q4_k_m.gguf
```

If the model still fails to load, the Rust crate surfaces the failure as
`LlamaError::ModelDownload` (HF resolver/cache) or
`LlamaError::ModelLoad` (everything else).

## First build is slow

The first build compiles `llama-crab-sys` and the selected llama.cpp
backends. Subsequent builds should reuse Cargo artifacts unless features
or source files change. CI and release workflows install extra
dependencies (Vulkan shader compiler, etc.) — see the workflows under
`.github/workflows/` if your local build matches the matrix.

## Allocation failures

If loading or context allocation fails:

1. Use a smaller quantized model.
2. Reduce `n_ctx`.
3. Reduce `n_batch` and `n_ubatch`.
4. Lower `n_gpu_layers`.
5. Disable optional features you do not need (e.g. `mtmd` for text-only
   work, `llguidance` if you do not use the alternative grammar
   backend, `hf-hub` for fully offline flows).

## Vision model does not see the image

Check all of these:

- The text GGUF and `mmproj` file come from the same model family and
  quantization lineage.
- The binary was built with the `mtmd` cargo feature
  (`cargo install llama-crab-server --features mtmd --force`).
- The prompt contains `default_media_marker()`.
- The image path is readable.
- The prompt template matches the model family.

Start with one known-good image and one short prompt before increasing
image size or context length:

```bash [Terminal]
llama-crab-server \
  --model /models/vision.gguf \
  --mmproj /models/mmproj.gguf
```

The HTTP server currently accepts `image_url` parts in multimodal chat
and rejects `audio_url` / `video_url` parts at bitmap load time with
`unsupported multimodal chat content part type: audio/video`. The Tauri
plugin accepts the same image inputs and rejects audio input with
`PluginError { kind: "mediaDecode" }`.

## Embeddings or reranking look wrong

Embedding models are more sensitive to pooling and backend details than
simple text completion. If vector dimensions, norms, ranking scores, or
crashes differ between environments:

1. Confirm the model path is the intended embedding or reranker GGUF.
2. Confirm embeddings are enabled with `LlamaParams::with_embeddings(true)`
   or the server's `--embeddings` flag.
3. For BGE-small semantic search, confirm `PoolingType::Cls`. For
   rerankers, confirm `PoolingType::Rank` and the `--reranking` flag.
4. Compare backend features such as `metal`, `openmp`, or other
   accelerators.
5. Validate embeddings separately from text generation; a chat model
   pass does not prove that pooling, vector dimensions, or ranking
   scores are configured correctly.
6. Be aware that `normalize` on the embeddings endpoint defaults to
   `false` (the previous draft of this page said `true` — the server
   behaviour is `false`).

## Server route returns disabled feature errors

`/v1/embeddings` requires the server to start with `--embeddings`.
`/v1/rerank` (and the `/v1/reranking`, `/rerank`, `/reranking` aliases)
require `--reranking`. Multimodal chat requires the `mtmd` cargo
feature on the server binary and the `--mmproj` flag at startup.

Examples:

```bash [Terminal]
llama-crab-server \
  --model models/bge-small-en-v1.5-q4_k_m.gguf \
  --embeddings

llama-crab-server \
  --model models/reranker.gguf \
  --reranking \
  --pooling rank
```

Repository wrappers and model download scripts are documented in
[Development](/contributing/development).
