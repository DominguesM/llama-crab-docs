Examples are executable documentation and live in
[`llama-crab-examples`](https://github.com/DominguesM/llama-crab-examples).
When adding or changing one:

1. Add the example crate in the `llama-crab-examples` repository.
2. Add it to that repository's root Cargo workspace.
3. Wire it into `run.sh` if it should be part of the public runner.
4. Document the expected model target and visible output.
5. Update the matching page in this Docusaurus examples section
   (1.text-and-chat, 2.embeddings-and-reranking, 3.multimodal,
   4.server, 5.structured-and-tools).
6. Mention the new example in the [Development](/contributing/development)
   wrapper target table so contributors can discover it.

For fast script validation, use the examples repository smoke test:

```bash [Terminal]
bash tests/examples_repo_smoke.sh
```

Functional model runs should use release mode unless the bug
specifically concerns debug behavior. The wrapper already pins
`cargo run --release`; raw `cargo run` invocations will be much
slower and may time out the smoke test.

When you add or change an example that exercises a public API
(`Llama::create_completion`, `Llama::load`, `LlamaParams::with_*`,
`MtmdInputChunks::eval`, `LlamaSampler::grammar`, etc.), cross-check
the code shape against the matching [Rust SDK](/rust/lifecycle) page
and the Cargo features list in [Cargo features](/reference/cargo-features).
The example must compile against the published `llama-crab` crate at
the version pinned in the wrapper (`0.1.8`).
