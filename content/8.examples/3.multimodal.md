Vision examples require two model files:

- a text GGUF,
- the matching `mmproj` projector GGUF.

The wrapper downloads both for supported targets.

The `mtmd` cargo feature must be enabled on the binary that runs the
example. The server needs `cargo install llama-crab-server --features
mtmd --force`; the Tauri plugin needs to be built with its own `mtmd`
feature; the Rust crate needs `features = ["mtmd"]` in the consumer
manifest.

## High-level vision

```bash [Terminal]
./run.sh vision gemma4
./run.sh vision lfm-vl
```

The binary loads the model, initializes `MtmdContext`, loads
`tests/fixtures/test_image.png`, tokenizes prompt plus image, evaluates
chunks (`MtmdInputChunks::eval` — the multimodal eval path, **not**
`LlamaContext::decode`), then samples an answer.

## Raw mtmd flow

```bash [Terminal]
./run.sh mtmd gemma4
./run.sh mtmd lfm-vl
```

This example stays closer to the `mtmd.h` flow and is useful when you
need to understand chunk evaluation and manual token feedback. Both
`MtmdInputChunks::eval` calls are wrapped in `unsafe { ... }` blocks
because the FFI takes raw `*mut llama_context` and `*mut mtmd_context`
pointers.

## LFM2.5-VL REPL

```bash [Terminal]
./run.sh lfm_vl
```

Starts an interactive vision-language REPL using
`models/LFM2.5-VL-1.6B-Q4_K_M.gguf` and its projector. Commands:

- `/image <path>` changes the active image.
- `/clear` resets chat history.
- `/exit` quits.

You can also run one prompt directly by passing model, projector,
image, and prompt to `run_lfm_vl`.

## Multimodal HTTP

```bash [Terminal]
./run.sh multimodal_http
```

Starts `llama-crab-server` with `--features mtmd`, the LFM text model,
and the matching projector. Send image content parts to
`/v1/chat/completions`. The server currently accepts `image_url` parts
and rejects `audio_url` / `video_url` parts at bitmap load time with
`unsupported multimodal chat content part type: audio/video`. Data
URLs (`data:image/...;base64,...`) and local file paths are both
accepted for `image_url`.

## Multimodal in the Tauri plugin

`tauri-plugin-llama-crab` exposes the same multimodal path through its
`mtmd` cargo feature. Once enabled, `load_model` accepts an
`mmproj_path` and the chat pipeline runs multimodal inference through
the Rust plugin. The Tauri TypeScript client forwards image parts to
the plugin — the previous "TS client rejects image content" behaviour
is gone. See [Tauri plugin](/tauri/plugin) for the full command list.
