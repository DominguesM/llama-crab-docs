`crates/llama-crab-server` exposes local OpenAI-compatible HTTP routes
backed by one loaded GGUF model. The server is single-model per process;
multi-model serving requires multiple processes.

The server is at version `0.1.6` (workspace-aligned with the rest of the
crates).

## Install the server

For normal use outside this repository, install the binary from
crates.io:

```bash [Terminal]
cargo install llama-crab-server --features mtmd --force
```

Add `--features hf-hub` (in addition to `mtmd`) when you want
`--model` to accept a Hugging Face repository id. The two feature flags
are independent and can be combined.

Then run it directly:

```bash [Terminal]
llama-crab-server --model models/qwen2.5-0.5b-instruct-q4_k_m.gguf
```

The examples below use the wrapper from the `llama-crab-examples`
repository.

## LFM server wrapper

```bash [Terminal]
./run.sh server_lfm
```

This starts the server with the LFM2.5-VL text GGUF. Pass server flags
after `--`:

```bash [Terminal]
./run.sh server_lfm -- --port 9090 --n-ctx 4096
```

The server defaults to `127.0.0.1:8080`. There is **no** graceful
shutdown handler — `Ctrl+C` aborts the process.

## Useful routes

The 12 routes the server actually exposes (verified against
`crates/llama-crab-server/src/main.rs`):

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Static 200 — does not check the worker. Deep readiness needs a real request. |
| `GET` | `/v1/models` | List the configured model. |
| `POST` | `/v1/completions` | Text completions (optional SSE streaming). |
| `POST` | `/v1/chat/completions` | Chat completions (optional SSE streaming). |
| `POST` | `/v1/embeddings` | Embeddings when started with `--embeddings`. |
| `POST` | `/v1/rerank` | Reranking when started with `--reranking`. |
| `POST` | `/v1/reranking` | Rerank alias. |
| `POST` | `/rerank` | Rerank alias. |
| `POST` | `/reranking` | Rerank alias. |
| `POST` | `/extras/tokenize` | Tokenize text. |
| `POST` | `/extras/tokenize/count` | Count tokens. |
| `POST` | `/extras/detokenize` | Convert token IDs back to text. |

See [Server: OpenAI API](/server/openai-api) for the full request and
response schema, and [Server: Streaming](/server/streaming) for the SSE
protocol details.

## Chat request

```bash [Terminal]
curl -sN http://127.0.0.1:8080/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{
    "messages": [
      {"role": "system", "content": "You are concise."},
      {"role": "user", "content": "Name three Rust smart pointers."}
    ],
    "template": "chatml",
    "max_tokens": 96,
    "temperature": 0.2
  }' | jq
```

Set `"stream": true` to receive SSE chunks. The terminal `data: [DONE]`
frame is always emitted, even when an `event: error` frame was emitted
before it.

## Multimodal request

Start the server with the `mtmd` feature and the matching projector:

```bash [Terminal]
./run.sh multimodal_http
```

Call:

```bash [Terminal]
curl -sN http://127.0.0.1:8080/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{
    "messages": [{
      "role": "user",
      "content": [
        {"type": "text", "text": "Describe this image in one sentence."},
        {"type": "image_url", "image_url": {"url": "tests/fixtures/test_image.png"}}
      ]
    }],
    "template": "chatml",
    "max_tokens": 64
  }' | jq
```

`image_url.url` accepts local file paths and `data:image/...;base64,...`
URLs. `audio_url` and `video_url` are parsed by the deserializer but
rejected at bitmap load time.

## Embedding and rerank modes

Embedding mode must be started with an embedding model:

```bash [Terminal]
llama-crab-server \
  --model models/bge-small-en-v1.5-q4_k_m.gguf \
  --embeddings
```

The embeddings endpoint's `normalize` parameter defaults to `false` —
pass `true` in the request body when the consumer code expects a
unit-length vector.

Rerank mode is wrapped by:

```bash [Terminal]
./run.sh rerank
```

Rerank mode requires both `--reranking` and `--pooling rank`.
