`@llama-crab/tauri` wraps the Tauri IPC commands with an OpenAI-like client shape. The runtime is a thin shim over `@tauri-apps/api` and depends on `@llama-crab/core` for the request/response contracts.

## Create a client

```ts title="Create a Tauri client"
import { LlamaCrabTauri } from "@llama-crab/tauri"

const client = new LlamaCrabTauri()

await client.models.load({
  model: "local",
  path: "/models/model.gguf",
  mobile_preset: "balanced",
})
```

The constructor accepts an optional `{ ipc }` to inject a custom `LlamaCrabTauriIpc` (useful for tests or non-Tauri runtimes that mimic the IPC contract).

## Model management

```ts title="Load, inspect, and unload a model"
const model = await client.models.load({
  model: "local",
  path: "/models/model.gguf",
  n_ctx: 4096,
  n_gpu_layers: 32,
})

const list = await client.models.list()
const sameModel = await client.models.retrieve(model.id)

await client.models.unload(model.id)
```

`ModelLoadParams` accepts the snake_case public fields (`n_ctx`, `n_gpu_layers`, `mobile_preset`, `pooling`, `mmproj_path`, `kind`, `embeddings`, `use_mmap`, `flash_attn`, `offload_kqv`, …). The IPC layer converts them to camelCase (`nCtx`, `nGpuLayers`, `mobilePreset`, `mmprojPath`, …) before sending `plugin:llama-crab|load_model`.

For embedding, rerank and multimodal models, pass the explicit runtime flags:

```ts title="Embedding and multimodal models"
await client.models.load({
  model: "embedder",
  path: "/models/embed.gguf",
  kind: "embedding",
  embeddings: true,
  pooling: "mean",
})

await client.models.load({
  model: "vl",
  path: "/models/lfm2.5-vl.gguf",
  kind: "multimodal",
  mmproj_path: "/models/lfm2.5-vl.mmproj",
})
```

`kind: "rerank"` enables embeddings and sets `pooling` to `rank` automatically.

## Chat completions

```ts title="Create a chat completion"
const completion = await client.chat.completions.create({
  model: "local",
  messages: [
    { role: "developer", content: "Answer in one sentence." },
    { role: "user", content: "What is local inference?" },
  ],
  max_tokens: 128,
  temperature: 0.7,
  tools: [{ type: "function", function: { name: "lookup", description: "Look up facts" } }],
  response_format: { type: "json_object" },
})

console.log(completion.choices[0]?.message.content)
```

`developer` messages are converted to `system` before they reach the internal request; the response follows the OpenAI chat-completion shape with `usage` populated.

## Streaming

```ts title="Stream chat tokens"
const abort = new AbortController()

const stream = await client.chat.completions.create(
  {
    model: "local",
    messages: [{ role: "user", content: "Count to three." }],
    stream: true,
  },
  { signal: abort.signal },
)

for await (const chunk of stream) {
  const token = chunk.choices[0]?.delta.content
  if (token) {
    process.stdout.write(token)
  }
}

abort.abort()
```

The client opens a Tauri `Channel<ChatCompletionChunk>`, listens for chunks, and yields them as an `AsyncIterable`. Each chunk carries a `requestId` that the client forwards to `plugin:llama-crab|cancel` when the `AbortSignal` aborts, so streams can be cancelled cleanly.

Text completions follow the same pattern. The streaming path also returns `AsyncIterable<CompletionChunk>` when `stream: true` is set on `client.completions.create`.

## Tools, structured output and logprobs

The Tauri client forwards the full OpenAI-like request shape (messages, tools, `tool_choice`, `response_format`, `logprobs`, `top_logprobs`) to the plugin. The plugin handles them, so no `UnsupportedFeatureError` is raised in the TypeScript layer for any of these.

- `tools` are serialised as `function` definitions; tool calls appear in non-streaming `choices[].message.tool_calls` and in `delta.tool_calls` of streaming chunks.
- `response_format` accepts `text`, `json_object` and the OpenAI `json_schema` shape. `json_object` maps to a built-in GBNF grammar; `json_schema` is converted to a GBNF grammar via `llama-crab`'s `schema_to_grammar`. You can also pass a literal GBNF string through `llama_crab.grammar` / `llama_crab.grammar_root`.
- `logprobs` / `top_logprobs` round-trip through the response's `logprobs` field on both non-streaming and streaming responses.

## Embeddings and rerank

```ts title="Embeddings and rerank"
const embeddings = await client.embeddings.create({
  model: "embedder",
  input: ["texto A", "texto B"],
  encoding_format: "float", // or "base64"
})

const rerank = await client.rerank.create({
  model: "reranker",
  query: "pergunta",
  documents: ["doc 1", "doc 2"],
  top_n: 2,
})
```

Embedding responses include `usage` (`prompt_tokens`, `total_tokens`). Rerank returns results sorted by descending `relevance_score`; `top_n` is honoured when provided.

## Extras: tokenize / detokenize

```ts title="Tokenizer helpers"
const { tokens } = await client.extras.tokenize({ model: "local", input: "hello" })
const { count } = await client.extras.tokenize.count({ model: "local", input: "hello" })
const { text } = await client.extras.detokenize({ model: "local", tokens })
```

`client.extras.tokenize` is a callable plus a `.count` sub-method. Both target the dedicated `tokenize` and `tokenize_count` commands.

## llama-crab options

llama-crab-specific options stay under `llama_crab` in the public request type and are mapped into the internal `Internal*Request` payload by the helpers in `@llama-crab/core`:

```ts title="Pass llama-crab-specific options"
await client.chat.completions.create({
  model: "local",
  messages: [{ role: "user", content: "Hello" }],
  llama_crab: {
    template: "chatml",
    top_k: 40,
    grammar: "root ::= object",
    grammar_root: "root",
    json_schema: { type: "object", properties: { answer: { type: "string" } } },
  },
})
```

`llama_crab.normalize` is also available on `embeddings.create` to override the default `normalize: true`.

## Multimodal

Image parts on chat messages follow the OpenAI shape and are accepted by the client as long as the Rust plugin was built with the `mtmd` cargo feature and the model was loaded with `mmproj_path`:

```ts title="Image part (mtmd feature)"
const completion = await client.chat.completions.create({
  model: "vl",
  messages: [
    {
      role: "user",
      content: [
        { type: "text", text: "What is in this image?" },
        { type: "image_url", image_url: { url: "data:image/png;base64,..." } },
      ],
    },
  ],
  max_tokens: 256,
})
```

The plugin currently supports base64 data URLs and local file paths. Audio input is not supported by the plugin and will surface as a `mediaDecode` error. Multimodal requests sent to a plugin built without `mtmd` surface as `multimodalNotEnabled`.

## Errors

When a plugin command fails, `@tauri-apps/api` rejects the underlying `invoke` with the `PluginError` payload. The `kind` discriminator is the same one listed in the [plugin page](/tauri/plugin#errors), so application code can branch on `invalidRequest`, `modelNotFound`, `workerSpawnFailed`, `workerDisconnected`, `workerPanicked`, `multimodalNotEnabled`, `multimodalSetup`, `mediaDecode` or `inference`. The shared `@llama-crab/core` errors (`InvalidRequestError`, `UnsupportedFeatureError`, `LlamaCrabError`) are thrown client-side before any IPC is sent.
