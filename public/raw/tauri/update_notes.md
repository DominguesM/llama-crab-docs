## What changed in the docs

### `content/4.tauri/1.plugin.md`

- Replaced the 7-command table (which listed `generate`, `chat_stream`, `get_loaded_models`, `get_model_info`, `cancel`, `load_model`, `unload_model`) with the real 14 commands exposed by the plugin (`load_model`, `unload_model`, `list_models`, `retrieve_model`, `create_chat_completion`, `stream_chat_completion`, `create_completion`, `stream_completion`, `create_embedding`, `create_rerank`, `tokenize`, `tokenize_count`, `detokenize`, `cancel`).
- Documented `init_with_config` and the `Config` struct (default context size, batch sizes, gpu layers, etc.).
- Documented the `mtmd` cargo feature: how to enable it, the dependency effect (`base64` + `image`), the `mmproj_path` field on `load_model`, accepted image inputs (data URLs and local paths), and audio not being supported.
- Documented the streaming protocol: chunks carry a `requestId` and cancellation goes through `plugin:llama-crab|cancel`. The terminal chunk always carries `finish_reason`.
- Documented the granular `PluginError` kinds (`invalidRequest`, `modelNotFound`, `workerSpawnFailed`, `workerDisconnected`, `workerPanicked`, `multimodalNotEnabled`, `multimodalSetup`, `mediaDecode`, `inference`) — the previous doc only listed `invalidRequest`, `modelNotFound`, `worker`, `inference`.
- Documented request/response fields: `LoadModelRequest` / `LoadModelResponse`, `MobilePresetName` (`low-ram` | `balanced` | `gpu-max`), `PoolingName` (`unspecified` | `none` | `mean` | `cls` | `last` | `rank`), `ModelKind` (`chat` | `completion` | `embedding` | `rerank` | `multimodal`).
- Documented the `kind` auto-behaviour: `kind: "embedding" | "rerank"` enables embeddings; `kind: "rerank"` defaults `pooling` to `rank`.

### `content/4.tauri/2.permissions.md`

- Replaced the 7-permission table with the real 14 `allow-*` and 14 `deny-*` permissions, mirroring the 14 `*.toml` files under `permissions/autogenerated/commands/`.
- Replaced the default permission set with the actual `default.toml` (14 `allow-*` permissions).
- Added a Tauri v2 capability file example (`llama-crab-default` with `llama-crab:default`) and a narrower `llama-crab-diagnostics` example to show how to grant only the commands a window needs.
- Documented the streaming pairing rule (capabilities that grant `allow-stream-chat-completion` should also grant `allow-cancel`).

### `content/4.tauri/3.typescript-client.md`

- Removed the obsolete `UnsupportedFeatureError` table for chat features (tools, tool_choice, response_format, logprobs, n>1, image_url, input_audio). The current Tauri client forwards all of those to the plugin; they no longer throw at the TypeScript layer.
- Documented the full client surface, including the new `client.completions.create` (with streaming), `client.embeddings.create`, `client.rerank.create`, `client.extras.tokenize` / `tokenize.count` / `detokenize`.
- Documented the streaming cancellation lifecycle (chunk `requestId` → `plugin:llama-crab|cancel`).
- Documented the multimodal path (mtmd feature + `mmproj_path` on `load_model` + base64 or path `image_url`).
- Documented the `llama_crab.*` options namespace, including `normalize` for embeddings.
- Documented the snake_case → camelCase payload mapping (`n_ctx → nCtx`, `n_gpu_layers → nGpuLayers`, etc.) inside the IPC layer.
- Documented the error surface (Tauri-side `PluginError` kinds and `@llama-crab/core` errors).

## Open questions for reviewers

1. **Internal request field stopSequences**: the previous doc claimed `stop → stopSequences`. The actual `InternalChatRequest` field is `stop: string[]` (and the internal request types in `@llama-crab/core` do **not** define a `stopSequences` field). The new doc reflects reality — confirm the old wording was a mistake.
2. **Capabilities and the mtmd feature**: the Rust plugin requires the `mtmd` cargo feature for multimodal chat, but the permission identifiers are unchanged. There is no separate `allow-multimodal-chat` permission. Confirm this is the intended model (image capability is gated by the cargo build, not by Tauri ACL).
3. **UnsupportedFeatureError**: the Tauri client source does not import or throw `UnsupportedFeatureError`. The class is still exported from `@llama-crab/core` for hypothetical other adapters, but the old doc table describing when the Tauri client throws it is gone. Confirm the removal is correct.
4. **Audio input**: typed in `@llama-crab/core` (`input_audio`), but the Rust plugin returns `mediaDecode` ("audio input is not supported by the plugin yet"). Doc mentions this caveat; consider filing a follow-up issue if audio support is on the roadmap.
5. **Streaming text completion shape**: `stream_completion` requires a single prompt and `n=1`; the doc says so. Verify that this constraint is the intended long-term behaviour or if the v0.1.x line will lift it.
6. **@llama-crab/tauri builds on @llama-crab/core**: the Tauri package's `package.json` has `devDependencies` for `tsup` and `vitest` but no `prepare`/`prepublishOnly` hook. Verify whether a release pipeline builds and ships both packages from the workspace.
